# 5B 高清资源生成与完整性核验

日期：2026-10-05。该报告对应当前本地构建图集，尚待用户验收。

## 完整覆盖

固定逻辑倍率为 2×。原版 15,849 个 PNG 路径全部对应高清 WebP，没有缺项或额外路径。图集分组如下：

| 资源组 | 文件数 | 生成方式 |
|---|---:|---|
| 角色行走、表情、欢呼和神灵覆盖 | 13,329 | 12 个角色的 SWF 原时间轴按 2×导出；角色动作以已选透明高清候选为基础，原始帧数、方向、锚点与时序不变 |
| 公司建筑与对话框 | 13 | 12 个公司建筑按原 SWF 边界 2×导出；公司 2–12 使用已有的 11 张高清候选并保留原形状边界/出生区坐标；对话框仍为插值位图 |
| 住宅与出售标记 | 100 | 96 张住宅等级/方向/颜色及 4 张出售标记由原 SWF 按 2×导出 |
| NPC、世界动画与中立住宅 | 810 | 原 SWF 的 790 帧世界时间轴与 20 张住宅帧按 2×导出 |

非角色共有 2,518 张公司、住宅、世界、互动和活动时间轴图像直接从 SWF 按 2×渲染；其余 2 张静态 PNG（地图、公司对话框）以预乘 alpha 的 Lanczos 处理。SWF 时间轴若内嵌低分辨率位图，重新渲染只会让外围矢量线条更平滑，位图细节仍受原来源像素限制。

已选公司候选关系在清单中逐一锁定：位图 178→公司 2，181→4，190→6，187→5，196→8，199→10，193→9，205→11，202→7，208→12，211→3。11 张候选经边缘连通黑底提取获得透明 alpha，写入离线工作 SWF 副本后，再用 JPEXS 导出公司精灵；原始 `play.swf` 未修改。候选图与 SWF 源哈希、形状 ID、透明像素数均列于高清清单。

## 尺寸、锚点和透明通道

PNG 转 WebP 使用 q98、alpha quality 100。对每张输出同时保存生成前 alpha 哈希，并验证解码后的 WebP alpha 哈希与透明/不透明预期。验证也核对源 PNG / SWF 哈希、角色候选哈希、原始帧 URL、时间轴帧号、动画时长、显示倍率和输出字节数。

有 262 张活动帧在 2×整数像素栅格上经 JPEXS 向上取整后比既有 2×逻辑画布短 1 像素。生成器只在右边缘和/或下边缘补透明像素，原点与逻辑锚点不动；每帧记录原渲染尺寸及补边数量。若任一维超过目标，构建会失败，不裁掉源图内容。

最近验证：15,849 张路径完整、15,849 张输出 SHA-256 和 alpha 均通过；15 个独立 `source` 文件与所有单独列出的角色/建筑候选哈希通过。WebP 总量 **244,614,960 字节**，含清单与镜像 JSON 的图集目录 **261,877,452 字节**。`hd-manifest.json` SHA-256：`9cb6b606e2dcb7491d15002e51752b6df4a616e1f0e6983e4fb14f3819bb5e28`。

`scripts/test_modern_hd_assets.py` 的 6 个检查通过，覆盖普通位图倍率、2×时间轴不重复放大、错误边界拒绝、alpha 损坏拒绝、世界图层对齐，以及活动帧补透明边缘不改锚点。

高清图集是被 `.gitignore` 忽略的可复现构建产物，没有加入 Git。准备 JPEXS 26.2.1、JDK 及 `scripts/requirements-modern-hd.txt` 中锁定的 Pillow/NumPy 后，可这样重建：

```sh
FFDEC_ROOT=/path/to/ffdec-26.2.1/full \
FFDEC_JAVA=/path/to/jdk/bin/java \
PYTHON=/path/to/python3 npm run assets:modern-hd

PYTHON=/path/to/python3 npm run verify:modern-hd-assets
npm run build:modern:hd
```

当前构建机为 JDK 26.0.1、JPEXS 26.2.1、Pillow 12.3.0、NumPy 2.3.5。重新生成只读取正式原始 SWF；候选补丁文件及导出中间物保留在忽略缓存 `.analysis-cache/hd-assets-5b/`。
