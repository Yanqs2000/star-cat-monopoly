## 结论与 ID 约定

下文的 `card ID` 是原版 `carddate`、`pcarddate` 使用的 **0-based 数组索引**，不是把卡片名称从 1 开始编号。`carddate` 每项为 `[名称, 奖券价格, 直接使用类型, usecard 处理帧, 说明]`，定义位于 `play.swf/scripts/frame_3/DoAction.as:504`，结构化副本见 `evidence/original-tables.json` 的 `carddate`。

## 共用使用流程、取消和消耗

当前人类玩家在可操作状态点击手牌时，`face` 里的 `card.onRelease` 要求 `_root.system_id == 0`，把手牌槽位写入 `_root.yesno_id` 并弹出确认框 (`.analysis-cache/ffdec/play.swf/scripts/DefineSprite_2049_face/frame_1/DoAction_2.as:134-163`)。确认按钮写 `yesno_id = 1`，取消按钮写 `yesno_id = 2` (`DefineButton2_1562`、`DefineButton2_1563` 的按钮脚本)；`checkYN()` 只有确认才 attach `usecard` 并跳根时间轴 15，取消直接清 `system_id` (`.../face/frame_1/DoAction_2.as:22-37`)。所以在处理帧开始前取消不会扣卡。

`usecard/frame_1` 将所选槽位保存为 `id`。处理帧通常在目标校验成功后调用同一份 `sortcard()`：减少计数并左移所选槽位 (`usecard/frame_1/DoAction.as:53-66`)。大多数目标失败分支只显示提示并退出，不调用 `sortcard()`，所以失败点击后卡仍在手牌；闭合的 frame 2/3 也不调用 `sortcard()`。本文件逐项标出两个例外：送神卡无附身时仍在收尾处消耗，信用卡使用从不调用 `sortcard()`。

所有坐标目标都通过 `getpoint()` 把屏幕坐标转为地图网格；点击道路空格时，它按鼠标所在象限改取相邻网格 (`usecard/frame_1/DoAction.as:10-51`)。除飞弹的五格完整性校验和招神卡的轴向距离框外，源码没有对鼠标目标设置玩家到目标的距离上限。

## 额外可达卡：ID 1 信用卡

### 获得

人类玩家经过银行时，银行周日关闭；非周日进入 `self_pg1()` 菜单 (`frame_4/DoAction.as:3372-3389`)。菜单项 `yesno_id == 5` 的申请分支要求：当前没有信用卡状态（`moneydate[pid][6] == 0 && [7] == 0`）、信用条件 `[5] >= 50`、手牌计数 `pcarddate[pid-1][0] <= 23`。通过后把 ID 1 插入手牌首位，计数加一，并写 `moneydate[pid][7] = 100000` 的信用额度 (`frame_4/DoAction.as:3496-3531`)。申请本身不扣奖券。

AI 玩家落在银行时走 `AI_build18()` 而不是人类菜单 (`frame_5/DoAction.as:1837-1847`)。该函数在 AI 等级大于 1、手牌未满且 `pcarddate[pid-1][1] != 1` 时同样插入 ID 1 并写 100000 额度 (`frame_5/DoAction.as:18-34`)；等级大于 2 且没有 `[8]` 债务时还会自动借入 100000 (`frame_5:3-12`)。源码只检查手牌第一槽是否为 ID 1，不扫描后续槽位，这是原版条件的具体边界。AI 仍没有调用 `usecard` 使用信用卡的分支。

### 使用

ID 1 的 `carddate` 类型为 1、处理帧为 4。处理帧把当前可用信用额度 `moneydate[pid][7]` 显示为计数器 (`usecard/frame_4/DoAction.as:1-17`)；计数器按钮将提交值限制在 0…显示额度，按确认后 `yesno_id >= 0`，写入现金 `[1] += amount`、已用信用 `[6] += amount`、可用额度 `[7] -= amount` (`frame_4:18-30`；计数器提交 `DefineSprite_1463_counter/frame_2/DoAction.as:1-8`)。这是即时现金提取，没有目标格、没有手续费或利息分支，信用卡本身不调用 `sortcard()`，可以重复提取直到额度为 0。计数器没有独立取消路径；提交 0 也是源码允许的结果。

## 3B / 3C 最小依赖

2026-09-16精读补正（以下结论优先于上表早期概括）：`usecard/frame_21`的`tenor_id==7`明确同时写`pd[pid][5]=c_id`和`pd[pid][6]=7`，因此招神附身期限是7天，不是没有期限赋值。`frame_18:99-125`先创建显示等级0的房屋，再把数据等级加一次，无主0级最终是1级，不是2级。原`moneydate[0][2]`为100000，购地卡对无主地付款进入该备用账户；现代可保留该金额，而不照搬无玩家0的冗余房屋计数。

### 医院 / 监狱的最小精确契约

源码中的三元组顺序是 **`[方向码, x 格, y 格]`**：`hospitaldate = [2,19,1]`、`jaildate = [4,21,41]` (`frame_3/DoAction.as:494-500`)。第一项同时被写入 `playerdate[pid][2]`，作为下一步移动的方向；`waydate1[2] = [-56,40]`、`waydate1[4] = [56,-40]`，所以它不是倒计时或状态码。对应的地图记录也直接是医院/监狱的特殊格：`builddate1[161]` 为类型 31、方向 2、坐标 `(19,1)`，`builddate1[163]` 为类型 32、方向 4、坐标 `(21,41)` (`evidence/original-tables.json` 的 `builddate1`；原始表由 `frame_6/DoAction.as:65-68` 初始化)。

送医院的共同写入是 `ppid._x/y = hospitaldate[1/2] * XL/YL`、`playerdate[pid][2] = hospitaldate[0]`、`[9] = 0`、`[3] = 3`、`[4] = 3` (`balk_pg7`, `frame_4/DoAction.as:529-598`；飞弹受伤分支同一位置写入，`usecard/frame_9/DoAction.as:319-369`)。公共设施被飞弹破坏时，发射者走监狱写入：`ppid._x/y = jaildate[1/2] * XL/YL`、`[2] = jaildate[0]`、`[9] = 0`、`[3] = 2`、`[4] = 5` (`usecard/frame_9/DoAction.as:425-468`)。因此 3A 只需要保留两套坐标/方向常量、状态 `[3]` 和计数 `[4]`；医院为状态 3/3 个 tick，监狱为状态 2/5 个 tick。

倒计时不是每个动画帧或每一步移动都减。完整回合循环在玩家 ID 回到 1 时推进日/月/周，随后才调用 `jin_pg()` (`frame_5/DoAction.as:1564-1607`)；`jin_pg()` 对所有活动玩家把 `[4]` 和附身字段 `[6]` 各减 1，最低由 `> 0` 守住 (`frame_4/DoAction.as:3105-3126`)。轮到状态 2/3 的玩家时，`run()` 调 `setfree_pg()` (`frame_5/DoAction.as:1788-1800`)：`[4] != 0` 就提示“还有 X 天”、设置 `sport_id=4,end_id=8` 并跳过该回合；`[4] == 0` 才显示玩家并仅把 `[3]` 改回 0 (`frame_4/DoAction.as:3255-3310`)。释放分支没有改写 `_x/_y` 或 `playerdate[][2]`，所以位置仍为医院 `(19,1)` / 监狱 `(21,41)`，方向仍为 2 / 4；之后 `goload_pg()` 从当前坐标和 `playerdate[][2]` 计算下一格 (`frame_4/DoAction.as:3310-3335`)。源码没有“返回受伤前位置”的写入，不能在 3A 依赖里补出该规则。

这对新版移动闭包有一个直接影响：医院释放后的第一步按方向 2 从 `(19,1)` 走向 `(18,2)`，监狱释放后的第一步按方向 4 从 `(21,41)` 走向 `(22,40)`（`waydate1` 的格步长为 `XL=56,YL=40`）。两个出口格分别是 `mapdate1[2][18] = 165`（类型 24 卡片格）与 `mapdate1[40][22] = 175`（类型 25 运气事件格）；对应 `builddate1[165]` / `[175]` 的坐标也分别为 `(18,2)` / `(22,40)` (`evidence/original-tables.json` 的 `mapdate1`、`builddate1`)。所以若 3A 允许玩家在释放后继续移动，地图闭包至少要覆盖这些出口及其后续可达路径。这不是新增卡牌规则，而是保留源码“坐标不归位、按方向继续走”所需的边界；其后是否触发卡片格/运气事件格的完整落点逻辑仍由移动/事件模块负责。

### 天使卡等级的字面结果

`usecard/frame_18` 的每个目标记录先读取原等级 `_loc11_ = builddate[...][4]`；无房屋实例时只创建视觉 `house`，随后无论是否刚创建都只执行一次 `builddate[...][4]++`（且仅在原等级小于 5 时），代码位于 `DefineSprite_3693_usecard/frame_18/DoAction.as:75-129`。因此最终元数据是 `0→1`、`1→2`、…、`4→5`；原等级 5 不变。无屋主地的 0 级也只变为 1 级。视觉实例的“先创建”不是一次元数据升级，不能解释为 `0→2`；有屋主且原等级 0 时，另有一次屋主房屋计数 `moneydate[owner][10]++`。普通落到附身天使时调用的 `faery_10()` 同样只做一次 `[4]++` (`frame_4/DoAction.as:1136-1263`)。

### 购地卡的空屋主与商店购买边界

`购地卡` 并不把“owner 为空”判为失败：它只要求当前记录类型 16 且 `_loc10_ != pid`，所以 `owner = 0` 会进入转让分支 (`DefineSprite_3693_usecard/frame_11/DoAction.as:13-28`)。此时计算出的 `pay` 直接执行 `mnd[_loc6_][2] += pay`，而 `_loc6_` 就是 0；因此源码把金额记入 `moneydate[0][2]` 这个“备用”行，再从买方先扣现金、不足扣存款，且没有总资金足够校验 (`frame_11:20-38`; `frame_6:68` 的 `moneydate[0]` 初始行)。新版若支持原版可达的无主地，最小模型需保留这个 reserve account 记账，或明确记录等价的不可见收款方；不能把钱凭空丢掉或把 owner 0 静默改成某个玩家。

卡片商店的购买是另一条路径：它只追加 `pcard`、扣奖券字段 `[3]`，不读取 owner、现金、存款或 `moneydate[0]` (`.analysis-cache/ffdec/play.swf/scripts/DefineSprite_3671_shopz/frame_1/DoAction.as:271-324`)。这两种“购买”不能共用一个 owner/资金结算分支。
