# 第一阶段：原版分析结果

分析对象是 `public/original/` 的 13 个原始 SWF，不是修改后的高清试用文件。检查日期：2026-09-12。

证据等级：**程序已确认**表示从原数据或调用链确认；**提取已验证**表示转换实际成功且检查了结果；**待运行复核**表示还需原版受控操作或字节码复核，不能直接当成已确认 Bug 或完整功能规格。

## 地图不是标准绕圈棋盘

**程序已确认：**`mapdate1` 是 43 行 × 41 列网格，`builddate1` 有 235 条记录，包括地点、配套建筑格、天空和占位。位移方向是 `[56,40] / [-56,40] / [-56,-40] / [56,-40]`；像素坐标由网格列 ×56、行 ×40 得到。

住宅记录为 112 条，按道路格与建筑格配对，实际 **56 块可购买住宅地，16 条街道**。证据是 `setNewGame()` 明确循环 1…56，用 `builddate[i*2]` 放置标牌，并从 `builddate[i*2-1][6]` 取方向。不能把 112 条记录解释成 112 块可购买地。

路网包含 16 个转角、8 个三岔路口、4 个十字路口。`selfveer_pg()` 排除来路的反方向后，在可选方向中随机选取；这段函数也在普通移动流程中调用，不能默认玩家每次路口都自由选路。

主地图 `map`（位图 ID 20）实际为 **2700×2552 合成底图**，道路、植被、云岛及大量固定建筑已经烘焙在其中。独立的 `gufen1…gufen12` 公司建筑、住宅、NPC、人物等另行叠加。因此之前替换部分独立建筑没有完成整张地图高清化。

证据：原始表格 [original-tables.json](evidence/original-tables.json)；[frame_3](evidence/source/play.swf/scripts/frame_3/DoAction.as) 的 `XL/YL/waydate1/mapdate1`；[frame_5](evidence/source/play.swf/scripts/frame_5/DoAction.as) 的 `setNewGame()`（约第 517 行起，住宅标牌约第 707 行起）；[frame_4](evidence/source/play.swf/scripts/frame_4/DoAction.as) 的 `goload_pg()/selfveer_pg()`（第 3312/3336 行起）。

## 普通规则样例

这些是源程序分支推导出的可核对样例，尚未逐个在原版受控对局中重放，不等同于已经通过的新版测试。

- 无人地价1500，现金100000，确认购买后现金98500，产权转给当前玩家。
- 同一玩家在同一街道拥有两块地价1500的地，等级分别0和1，普通过路费为 `1500*0.4 + 1500*0.8 = 1800`。不能按本次落脚地单独算600或1200。
- 当前升级等级2，普通升级费用300，成功后等级3；常规升级上限5。
- 普通过路费1800，付款者现金500、存款100000，则现金归零、存款变为98700；地主存款增加1800。
- 财神附身免缴该住宅路费，穷神附身使该路费加倍。这是状态效果，不应混进固定地价表。

证据：[frame_4](evidence/source/play.swf/scripts/frame_4/DoAction.as) `end_pg16()` 第1371行起；原租金系数 `hiredate=[0.4,0.8,1.5,3,6,10]` 位于 [frame_3](evidence/source/play.swf/scripts/frame_3/DoAction.as) 第506行。

## 卡牌定义与开放范围

程序的常规随机池为：控骰、障碍、地雷、飞弹、购地、炒地、拆屋、天使、恶魔、怪兽、招神、送神、均富、均贫、停留、查税，共16种。

`outcard()` 从ID5开始，仅选处理帧字段不为0的项目；商店使用同样过滤。信用卡定义有处理帧但不在这个常规池，部分卡的定义存在而处理帧为0；这些需查其他获得入口，不应直接删除，也不应擅自补全为新功能。

建议第一版保留原版可达行为；未开放定义列为资料，只有确认是原版Bug且完成差异记录后才修改开放范围。

## 动画与声音转换验证

角色根帧标签为：1右下、31左下、61左上、91右上。`brow_pg(tmp)` 按 `(方向-1)*30 + 状态偏移` 选择根帧。角色根舞台56×40不是人物包围盒，直接按舞台裁切会丢掉头部。

卷毛的普通行走子精灵为130/308/488/664，每个24帧。已实际导出96张RGBA帧，并生成4个透明APNG与[联系表](evidence/movement/contact-sheet.png)。每方向导出帧尺寸分别72×96、68×97、74×99、71×100；不能把这些宽高直接当成通用游戏坐标。

这只验证了**卷毛普通行走**的提取可行性，不代表12角色全部表情、受伤、投掷、特殊状态或阴影已经适配。第三阶段之前必须建立每角色动作映射并审查缺失动作。资产清单需保存原根/子精灵矩阵与锚点，之后才能打包图集。

音频导出了19个非空MP3；另有一个44字节、0采样帧的空WAV，占位文件不计为第20段音频。原音频多为11025Hz单声道，按用户要求原样沿用，不声称升级了音质。

## 迁移中的关键风险

| 风险 | 已见证据 | 处理方式 |
|---|---|---|
| 规则藏在时间轴 | 骰点第36帧决定，第65帧写step_id；建房表现回写show_id | 核心状态机与表现调度分离，明确一次性事件与动作完成通知 |
| 视觉与规则共用随机数 | 117处random调用包括云、对白、骰子、股价、AI | 新核心注入规则随机源；原版对照记录语义结果，不承诺相同seed即可相同结局 |
| 业务数据依赖像素/临时实例 | map按ppid像素坐标索引，存档保存人物当前帧与实例位置 | 核心保存网格、方向和显式状态，渲染从状态恢复 |
| 动态函数调用 | `this['end_pg'+pg_id]()`、NPC处理函数名拼接 | 每个原处理ID建立显式映射，遗漏时失败而非静默跳过 |
| 暂存内容被误当开放功能 | 37种卡定义、16种普通抽卡池 | 以可达入口和实际行为确定范围 |
| 资源预乘alpha/裁剪 | 地图边缘与阴影需专门检查；角色超过原舞台 | 对照原播放器检查混合方式、锚点与整体轮廓，不能只检查PNG有alpha |
| 过早“改进AI” | yesno_AI在处理帧直接选择确认，另有专用银行AI | 先复现实际策略，不把简单AI认定为Bug或擅自增强 |
