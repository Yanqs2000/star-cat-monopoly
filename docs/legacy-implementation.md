# 星猫大富翁 · Star Cat Monopoly

4399 经典 Flash 小游戏《星猫大富翁》的工程化复刻 —— **3D 版**。

不是单文件 HTML —— 这是一个标准的 **Vite + TypeScript + Vue 3 + Pinia + Three.js** 工程，
核心规则层是零依赖的纯 TypeScript，可以脱离浏览器直接单测和跑整局模拟。

```bash
npm install
npm run dev        # 开发服务器 → http://localhost:5173
npm test           # 54 个单测 / 集成测试 / 整局模拟
npm run build      # 类型检查 + 生产构建
```

棋盘是真正的 3D 场景（Three.js）：等距斜俯视角、可拖拽旋转、可滚轮缩放；
灰色环形马路 + 彩色地块 + 随等级生长的卡通楼房 + Q 版猫棋子 + 会翻滚的 3D 骰子。
HUD、面板、日志仍是 DOM，叠在画布上方。

> 关于原版：4399 那款是 2D Flash 游戏，但美术是把 3D 模型渲成的贴图（等距城市街区）。
> 本作直接用实时 3D 还原那个观感。**原版没有 3D 版本**。

## 复刻了什么

| 系统 | 内容 |
|---|---|
| **骰子力度控制** | 按住蓄力，松手按力度换算点数。轻点小步数（精细走位），重甩大步数（冲圈抢地）；满力度有「手滑」风险 |
| **地产** | 40 格棋盘、8 个色组共 24 块地；买地、盖房（3 级）、收过路费、垄断整组租金翻倍 |
| **银行** | 存款按**存放天数**计单利；现金不足会强制支取存款，但会损失未结利息 |
| **股市** | 6 只股票，带均值回归的随机游走；**只能用现金交易**，现金不足强制扣存款 |
| **彩市** | 用奖券刮彩票，头奖 2 万 |
| **游乐场** | Canvas 小游戏：左右移动接住掉落的财富，金币 2 分、银币 1 分、炸弹 −2 分 |
| **神明** | 财神（过路费减半）/ 福神（投资必成 + 送卡）/ 衰神（买地失败 + 丢卡）/ 穷神（过路费 +50%） |
| **卡片** | 路障卡、机器娃娃、抢夺卡、盖屋卡、拆屋卡、暂停卡、迎神送神卡 |
| **事件格** | 新闻（天上掉馅饼 / 飞来横祸）、魔法屋、卡片格、税务局、监狱 |
| **角色** | 12 星座星猫，各带一个主动技能 |
| **胜利条件** | 淘汰制 / 垄断制 / 长跑制 / 财富制，开局可选 |

初始资源对齐原版：现金 10 万、存款 10 万、3000 股股票、200 张奖券。

## 两点必须说明

**1. 美术是原创的。** 原版是《快乐星猫》IP 美术，本项目**没有复制任何原版素材**——
12 只猫全部由 `src/assets/catSvg.ts` 按角色数据程序化生成 SVG。
角色名（卷毛、阿牛……）保留在 `src/core/config/characters.ts` 里方便你对照原游戏，
想换成自己的角色，改这一个文件即可，其余代码全部数据驱动。

**2. 数值是「依据攻略重建」的。** 原版精确数值（地价表、利率、股价曲线）没有公开资料，
本项目按攻略描述的经济结构设计了一套自洽数值，全部集中在 `src/core/config/economy.ts`。
所以它是**玩法复刻**，不是逐数值还原。

## 工程结构

```
src/
├── core/                    ★ 纯 TypeScript，零 DOM / 零 Vue / 零 Three 依赖，100% 可单测
│   ├── types.ts             GameState / Player / Tile / Card / God / GameEvent
│   ├── dice.ts              力度 → 点数概率分布
│   ├── config/              board · characters · cards · gods · stocks · economy
│   ├── rules/               rent · bank · stock · money
│   ├── engine/
│   │   ├── GameEngine.ts    状态机 + 回合流程 + 规则校验
│   │   └── rng.ts           可复现随机（mulberry32）
│   └── ai/AiPlayer.ts       AI 决策（纯函数）
├── render3d/                ★ Three.js 渲染层（3D 化只加了这一层）
│   ├── SceneManager.ts      渲染器 / 相机 / OrbitControls / 循环 / dispose
│   ├── layout3d.ts          格子索引 → 世界坐标、文字朝向（纯函数，可单测）
│   ├── CityBoard3D.ts       场景编排 + 状态差异同步
│   ├── TileMesh / BuildingMesh / TokenMesh / DiceMesh / textures / scenery
│   └── …
├── stores/gameStore.ts      Pinia：包装引擎，暴露响应式视图状态
├── components/
│   ├── board/Board3D.vue    3D 棋盘的 Vue 包装（桥接 store → 场景）
│   ├── hud/                 玩家卡片 · 蓄力骰子
│   └── panels/              银行 / 股市 / 彩市 / 商店 / 地产 / 提示 / 日志
└── assets/catSvg.ts         程序化星座猫 SVG
tests/                       Vitest：规则单测 + 整局模拟 + 系统覆盖度
```

### 四条架构约束

**1. `core/` 是纯的。** 所有规则是纯函数，不 import 任何 Vue / DOM / Three。
「过路费算错」「利息算错」这类 bug 能被单测直接抓住。

**2. 引擎发事件，渲染层消费事件播动画。** 引擎同步结算并产出 `GameEvent[]`
（`DICE_ROLLED` / `MOVED` / `TOLL_PAID` / `CARD_PLAYED` …），
渲染层按队列播放。逻辑永远不碰 DOM，动画永远不回写状态。

**3. 随机全部走种子 RNG。** `rngState` 存在 `GameState` 里，
「同一颗种子 + 同一串操作 = 同一局」，测试和回放都靠它。

**4. 3D 层只做差异同步，绝不重建场景。** `state` 每次 dispatch 都是新对象，
但 3D 层只比对每格的 `owner` / `level` / `barrier` 三个字段，
变了才动对应的物件；地块贴图只画一次（拥有者色、建筑、路障都是独立物件）。

**状态用 `shallowRef` 持有，不做深层响应式**——每次 dispatch 整体换新对象，
「一个事件 = 一次界面更新」，避免 proxy 开销和局部失效问题。

### 3D 层的一个关键规则

**只有相邻格才做位移动画，非相邻一律瞬移。** 因为进监狱、卡片传送这类位移
不会发出逐格 `MOVED` 事件，`visualPos` 会整段跳变——直接插值会让棋子斜穿棋盘。
`layout3d.isAdjacent()` 判断索引差是否为 1（含 39→0 环绕），是这套动画的地基。

## 测试

54 个测试，分三层：

- **规则单测**（`dice` / `rent` / `bank` / `money`）：把公式和边界钉死。
  比如骰子力度必须「有掌控感但不精确」——0~0.8 区间期望点数单调递增，
  但满力度不能比 0.8 更划算（手滑代价），否则机制会退化成「永远满蓄力」。
- **引擎集成**：非法动作被拒绝且状态对象原封不动；破产清算；四种胜利条件；
  存取款按天计息；股市现金不足强制扣存款。
- **整局模拟 + 系统覆盖度**：用真实 AI 跑 12 局完整对局，
  断言购地/卖地/盖房/过路费/股市/彩票/卡片/神明/监狱**每一项都被触发过**——
  这是抓「某个系统其实是死代码」最有效的手段（开发过程中它确实抓到了两处）。

```bash
npm test
```

3D 渲染另外用无头 Chrome + SwiftShader 实跑验证：探测 `window.__scm3d.ok`（WebGL 是否可用、
是否软件渲染、渲染帧数），把棋盘 8 个角投影到屏幕坐标断言全在视口内，
再用几何投影校验四条边的文字朝向（近侧两边可正读，远侧两边倒置——转动视角即可读）。

## 开发态调试

`npm run dev` 下，浏览器控制台里有 `window.__scm`：

```js
__scm.state                       // 当前完整游戏状态
__scm.state.players[1].cash = 1e6 // 直接改数值（仅调试）
__scm.setSpeed(0)                 // 0=跳过动画 1=正常 2=加速
__scm.roll(0.05)                  // 以指定力度掷骰
__scm.dispatch({ type: 'END_TURN' })
```

## 已知边界

- 数值平衡没有做过真人长时间试玩，只做了自动化模拟；`config/economy.ts` 里所有常量都可以调。
- AI 是启发式的，能打完一局但不算强；`AiPlayer.ts` 里每个决策点都有注释说明取舍。
- 原版的多地图（台湾/澳门/广州/上海）与闯关模式没有做——棋盘是数据驱动的，
  加地图只需要往 `config/board.ts` 里加数据。
