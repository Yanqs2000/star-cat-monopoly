# 原版缺失查询功能实施计划

> 执行方式：在隔离 worktree 内继续完成用户已授权的功能补齐，采用 TDD，最后提供实际对局供用户确认。

**Goal:** 在地图重构后的 b874227 上补齐地图信息、资产排名、股票/全员持股总览、帮助，并验证本地存档服务闭环。

**Architecture:** 沿用 Vue/Pixi 和现有 GameState。查询使用纯函数派生，不改变规则、RNG、存档 schema 或地图素材。资产、股票、持股、帮助共用一个可关闭的查询面板；打开时暂停，关闭恢复原暂停状态。地图通过原网格拾取显示当前格信息，拖动及用卡选目标不触发查询。

**Tech Stack:** Vue 3、TypeScript、Pixi 8、Vitest、Playwright、本机 Chrome、Node 24、现有 Fastify/SQLite。

## 范围与决策

- 四个缺口来自本聊天 2026-10-18 原版功能审计，不重做美术，不扩展网络多人、自动存档或旧 Flash 存档导入。
- 沿现有侧栏增加查询入口，选人和对局均可打开帮助；复用当前视觉体系，不另做页面设计。
- 原 asset_pg 住宅估值为原住宅字段[9]加 100*level*(level+1)/2；住宅[9]初始为0，买地/炒地不修改它，不把当前地价擅自当资产估值。需以源代码及受控样例记录。
- 资产表列现金、存款、股票估值、房产估值、已用信用、贷款、净资产、土地/建筑/手牌/奖券及排名；淘汰者不参与存活排名，同值按席位排序。
- 股票行情为1–12；全员持股覆盖1–15，包括非上市公共事业，展示均价、董事、峰/谷、承销价和待认购池。
- 查询在帮助/资产/股票/持股间切换不恢复对局；全屏、Escape、焦点、加载失败、AI移动或小游戏中打开均需检查。
- 已有存档实现先运行独立数据库与后端验证；只在实测发现根因时改代码，不能把后端未启动误称缺实现。

## Review Focus

1. 读取查询不能消费RNG、复制结算或改变暂停前后的状态。
2. 地图建筑格与道路格配对、公司动态分配、空地及失物招领分支必须使用当前局数据。
3. 资产估值不能按现价重复计算公司建筑、将可用信用计入净资产或令淘汰者夺得排名。
4. 对话框不能放行背景键盘/鼠标，关闭恢复焦点及原暂停/速度，全屏下仍可见。
5. 存档真实HTTP/SQLite读回必须相等，失败不能丢当前局；新地图保留。
