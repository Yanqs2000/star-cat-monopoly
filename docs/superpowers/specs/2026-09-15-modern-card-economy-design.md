# 3A 卡目录、背包与商店设计

本子模块服务完整3A目标，不包含卡牌使用效果或界面，完成后仍继续其余3A覆盖表。沿用已认可的纯规则架构，无新运行依赖。

离线导出原37行卡定义为资料，按原`outcard`筛选从ID5开始且处理帧不为0的16种常规卡。资料中存在某卡不等于开放其获得或使用；信用卡及其他入口由专项卡牌证据决定，不向普通随机池添卡。

每人原开局背包为`[9,6,7,27,5]`，纯模型用按顺序排列的卡ID数组表达，不保留原数组第0项计数与24格空位。数组长度就是实际数量，上限24。卡片格未满时抽一次，满时不抽取、不修改，返回最后一张用于原通知语义。

商店初始200奖券来自玩家开局资金；商店模块只接受传入奖券余额，不自行初始化全局玩家。每次进入生成固定6槽`[5,6,7,5,9,6]`和独立随机6槽，允许相同卡重复。槽位售出标为null，重绘不刷新。购买按原价花奖券，卖出按原价返券，保持余下背包顺序。失败不改变任何值，成功不改变规则随机源。AI是否访问由控制层按原经过分支处理，不能在此发明采购AI。

本模块输出明确结果和新数组，控制器稍后负责用卡/交易阶段、暂停、返回、一次性命令。UI只传选择，不传价格。使用卡效果由另一个纯规则模块实现，不将神灵、炸弹或财产规则混入商店。

来源：phase-3a-events-evidence.md商店段、原`outcard`、原卡表、原pcarddate及shopz脚本。背包中未开放定义可以作为原证据被解析，但无法通过本模块的普通获得路径产生；对卖卡不擅自附加禁止条款。
