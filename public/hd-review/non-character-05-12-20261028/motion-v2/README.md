# 05—12 动画自主检测与修正

地雷眼睛修订（r4）：补回下方两只半睁眼内的黑色瞳孔，上方白圆仍为高光。保留±6°摆动、3逻辑像素起伏和透明留白，整段160帧使用同一张新纹理。原缺瞳孔母版保留用于追溯。

技术结论：上一版生成姿态切换不合格；当前连续动画资源通过检查。正式游戏尚未接入，整局性能未验证。

## 找到的问题

- 四种掉落物每秒采样60次均只有10个不同画面，连续6次采样不变。杂志侧转时宽度单步跳变23—24逻辑像素。
- 地雷80帧只有3个姿态，最长保持1.2秒。
- 路障亮灭状态使用不同生成图，牌面固定区域的平均RGB差约34.98，车架会随灯光发生变化。

## 修正方式

- 路障：固定同一套车架纹理，仅灯光变化。保留原有亮灭周期。
- 地雷：固定同一张纹理，以连续刚性变换摆动，循环时长保持约2.667秒。按用户反馈将摆幅从±1.25°增至±6°、上下行程从0.36增至3逻辑像素；四周增加4逻辑像素透明留白，不缩小地雷。
- 银币、杂志：固定同一张高清图案，连续投影、旋转；保留1秒循环，输出60帧。印刷图案不会在不同生图之间切换。
- 法院高亮、Ready、Win：保留原SWF矢量及原本有意的闪烁，不把提示闪烁误判成运动卡顿。
- 05手牌栏、06计算器是静态UI，不需要生成运动帧。

## 实测结果

- 四种掉落物60次浏览器采样有59个不同画面，连续重复次数为1；两次相同画面不相邻，对应旋转中的同向边缘。
- 三种杂志的最大相邻宽度变化降至5—5.5逻辑像素。银币为0.5像素，地雷为0.25像素。
- 地雷160个渲染帧全部不同；加大幅度后的160帧均无裁切。更新后Chrome实播4秒：241个帧间隔，95分位16.7ms，最大16.8ms，无超过50ms的间隔。
- 路障固定牌面平均RGB差降至0.154，车架保持稳定；灯光仍按原时序闪烁。
- 所有修正资源的第0帧与完整周期后的画面逐像素一致，下一周期下一帧也一致。
- 7个修正资源的WebP解码结果与渲染帧的alpha、可见RGB完全一致，未引入有损编码变化。
- 动画页面8秒rAF采样：中位16.7ms、95分位16.7ms，最大49.9ms；无超过50ms的间隔。
- 对照视频：1280×840，60fps，480帧，8秒。最终Chrome实播4秒报告启动丢1帧，5秒隔秒采样中后续没有新增掉帧。
- 12条动画末帧返回首帧的24项界面检查、计算器预览和390像素宽界面通过；无脚本错误或请求失败。
- 62个受保护来源和224个原候选PNG指纹未变。项目原有750项测试通过；测试命令为npm test，执行时Node为26.12.0。

## 文件

- `comparison.mp4`：左侧旧切图、右侧修正动画的8秒实播对照。
- `animations/*.webp`：保留透明通道的无损循环动画。路障方向3复用方向1，方向4复用方向2。
- `mine-eyes-verification.json`：补眼后的逐帧边界、循环、无损解码和浏览器检查。
- `mine-amplitude-verification.json`：地雷加大摆幅后的逐帧边界、指纹和浏览器检查。
- `verification.json`：渲染帧、循环、文件指纹与无损解码记录。
- `browser-verification.json`：真实Chrome页面和媒体播放结果。
- `baseline-*.json`、`corrected-*.json`：先失败、后通过的回归证据。
- `tests/check-motion.cjs`、`tests/check-road.py`：实际浏览器画面连续性和固定牌面稳定性检查。

图案源仍是此前的GPT内置生图母版，未重新绘制人物。原姿态图集保留为纹理来源，不再作为当前连续动画的切帧序列。
